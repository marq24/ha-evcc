# Contributing

Thanks for your interest in contributing to this project.

This is a community project maintained in my spare time. Bug reports, technical findings, documentation improvements, and pull requests are welcome.

## Issues and feature requests

Before opening an issue, please check the documentation and existing issues and provide enough information, logs (on debug level), use of home assistant integration _generate diagnostics data_, and context to understand the problem.

Feature requests are evaluated not only by whether they can be implemented, but also by:

- project scope and architecture;
- existing Home Assistant functionality;
- reliability and risk of false positives;
- configuration complexity and backward compatibility;
- long-term maintenance and support.

A feature may therefore be declined even if someone offers to implement it.

**A pull request provides an implementation. It does not remove the long-term maintenance responsibility from the project maintainer.**

As a general design principle, these integrations prefer to expose reliable data provided by the underlying device or service. Interpretation of that data should remain with Home Assistant or user automations where appropriate.

For larger changes or new entities, please discuss the approach in an issue before starting implementation.

## AI-assisted contributions

Using AI tools for coding, research, translation, or writing is allowed.

However, you remain fully responsible for everything you submit. Please make sure that you:

- have reviewed and as human **understand** the submitted content;
- **clearly** indicate which parts of the contribution were generated by AI;
- can **explain** the technical approach **yourself**;
- **verify** technical **claims** and generated code;
- respond directly to architectural, scope, and maintenance concerns raised during review.

**AI should assist the discussion, not replace it.**

Repeatedly submitting generated variations of the same proposal without addressing previous maintainer feedback is not considered productive discussion.

## Technical decisions and conduct

Technical disagreement is welcome. Please keep discussions constructive and focused on technical arguments.

Not every technically possible feature will become part of the project. Issues may be closed as `not planned` when a proposal does not fit the scope, architecture, or long-term maintenance goals of the integration.

Please keep discussions respectful. Personal attacks, harassment, or repeated attempts to restart an already closed discussion may result in the discussion being locked.
